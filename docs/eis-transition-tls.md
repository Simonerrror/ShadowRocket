# Временный TLS-доступ к ЕИС через Shadowrocket 2.2.90

## Вывод

Полное безопасное решение штатными средствами Shadowrocket 2.2.90 не реализуется. Нативный MITM открывает ЕИС, но `skip-server-cert-verify` отключает проверку upstream-сертификата для всех хостов итогового списка MITM. Shadowrocket не поддерживает отдельный upstream pin для домена и не отключает правило по дате.

Для текущего профиля допустим ограниченный аварийный вариант: включить модуль `modules/eis_transition_tls.module` только на время перехода. Сейчас базовые профили и установленные модули не содержат других MITM-хостов. Перед каждым включением повторите эту проверку.

Для постоянного автоматического срока действия используйте локальный TLS-адаптер после отдельного согласования. Адаптер должен доверять только проверенному корню ЕИС, сохранять проверку имени `zakupki.gov.ru` и прекращать работу после заданной даты.

## Подтверждённый синтаксис 2.2.90

Установленный `MacPacketTunnel` распознаёт параметры:

```ini
[MITM]
hostname = zakupki.gov.ru
skip-server-cert-verify = true
ca-p12 = <PKCS#12 data>
ca-passphrase = <passphrase>
```

Модуль намеренно не содержит `ca-p12` и `ca-passphrase`. Не храните закрытый ключ CA в Git. Создание CA, установка доверия и включение модуля требуют отдельного подтверждения.

`hostname` проходит через `mitmTrie`. Shadowrocket расшифровывает соединение только после совпадения хоста и порта. Параметр `skip-server-cert-verify` хранится одним флагом в `DLWRuleManager` и передаётся в upstream TLS как `GCDAsyncSocketSSLAllowInsecure` или отключённый OpenSSL verify mode.

Модуль использует `hostname = zakupki.gov.ru` без `%APPEND%`. Это заменяет итоговый список MITM и не сохраняет неизвестные хосты из базового профиля. Порядок включённых модулей всё равно влияет на итоговую конфигурацию; после изменения модулей проверьте итоговый список в Shadowrocket.

Параметр `hpkp` относится к `DLWServer`, то есть к TLS-сертификату прокси-узла. Он не задаёт pin сертификата целевого сайта ЕИС.

## Домены

Разрешён один точный хост:

```text
zakupki.gov.ru
```

Карточка закупки, печатные формы и наблюдаемые ссылки вложений `/44fz/filestore/...` используют этот хост. `www.zakupki.gov.ru` является CNAME на `zakupki.gov.ru`, но контрольный URL не перенаправляет на `www`. Не добавляйте `www` или `*.zakupki.gov.ru` без сетевого журнала конкретного рабочего сценария.

## Причина ошибки

Сертификат `*.zakupki.gov.ru` покрывает `zakupki.gov.ru` и действует с 17 марта 2026 года до 17 марта 2027 года. Сервер передаёт цепочку до самоподписанного `Russian Trusted Root CA`. Строгий запрос завершается ошибкой проверки цепочки; имя и срок leaf-сертификата корректны.

## Модель угроз

- CA Shadowrocket после установки доверен Chrome на уровне системы. Компрометация его закрытого ключа позволяет выпускать сертификаты для любых имён.
- `hostname = zakupki.gov.ru` ограничивает вход в MITM. Не используйте `hostname=*`, wildcard или `%APPEND%`.
- Нативный `skip-server-cert-verify` не проверяет upstream-сертификат ЕИС. Атакующий между Shadowrocket и ЕИС может подменить upstream TLS.
- Новый MITM-модуль может расширить итоговый `hostname` и унаследовать отключённую проверку. Перед включением проверьте все активные модули.
- Храните закрытый ключ CA только локально. Не помещайте `ca-p12`, passphrase или экспортированный CA в репозиторий.
- Поле `#!expires=2027-03-16` контролируется тестом репозитория. Shadowrocket не исполняет это поле и не отключает модуль автоматически.
- Локальный адаптер должен слушать только loopback, принимать CONNECT только к `zakupki.gov.ru:443`, отклонять другие SNI и завершать работу после срока политики.

## Варианты

1. Нативный MITM: пригоден только как временный аварийный доступ в текущем профиле. Он не сохраняет upstream hostname verification.
2. SPKI или fingerprint pin: не реализуем для целевого сайта штатно. Доступный `hpkp` относится к прокси-узлу.
3. Локальный TLS-адаптер: рекомендуемый вариант для автоматического срока. Shadowrocket направляет точный `DOMAIN,zakupki.gov.ru` на loopback HTTP CONNECT proxy. Адаптер доверяет только утверждённому корню или SPKI, проверяет имя и дату, затем передаёт трафик.

Не запускайте локальный адаптер как открытый HTTP proxy. Он должен отклонять произвольный CONNECT до установления upstream-соединения.

## Проверка перед включением

1. Откройте список активных модулей Shadowrocket.
2. Проверьте, что ни один другой модуль не содержит `[MITM]`, `hostname` или `skip-server-cert-verify`.
3. Проверьте итоговый список HTTPS Decryption. В списке должен быть только `zakupki.gov.ru`.
4. Создайте и установите CA только после отдельного подтверждения.
5. Включите модуль только после выполнения предыдущих проверок.

## Тест-план после отдельного подтверждения

1. Откройте контрольный URL в обычном Chrome. Проверьте загрузку карточки и одного вложения.
2. Откройте обычный HTTPS-сайт. Проверьте, что issuer сертификата остался исходным, а не CA Shadowrocket.
3. Откройте `https://www.zakupki.gov.ru/`. Проверьте, что Shadowrocket не расшифровывает соединение без отдельного разрешения.
4. Проверьте редирект на неизвестный домен. Shadowrocket не должен расшифровывать целевой домен.
5. Для локального адаптера отправьте CONNECT к неизвестному домену и к другому порту. Ожидайте отказ до upstream-соединения.
6. Проверьте, что в профиле отсутствуют `hostname=*`, глобальный `skip-server-cert-verify` вне изолированного модуля и параметры запуска Chrome с отключённой проверкой сертификатов.
7. Отключите модуль. Контрольный URL должен снова проходить штатную проверку Chrome и воспроизводить ошибку, пока системное доверие к цепочке не изменится.
8. После исправления цепочки ЕИС удалите модуль и CA Shadowrocket. Повторите проверку контрольного URL без исключения.

## Срок

Удалите модуль не позднее 16 марта 2027 года. Это жёсткий верхний предел, выбранный на один день раньше окончания текущего leaf-сертификата. Фактический переходный период может закончиться раньше; удалите модуль сразу после восстановления штатной проверки Chrome.
