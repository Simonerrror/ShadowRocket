# Clash Verge Rev

> `clash_config.yaml` больше не поддерживается вручную отдельно: он генерируется из
> `shadowrocket.conf` через `scripts/build_clash_config.py`. Правила общие с
> Shadowrocket, а группы выбора адаптированы для Mihomo.
> Rule providers используют `format: text`: их источники — текстовые списки
> Shadowrocket, а не YAML с полем payload.
> Для автопроверки серверов `proxy-providers.Main-Sub.health-check` и группы «Режим»
> используется `https://www.youtube.com/favicon.ico`. Интервал проверки провайдера — 780 секунд;
> для группы «Режим» — 180 секунд, tolerance — 100.

## Выбор серверов

Свежий общий шаблон и браузерный генератор используют одну видимую группу
**Режим** типа `url-test`. Она автоматически выбирает доступный узел с наименьшей
задержкой. Список узлов и проверка задержек доступны внутри группы.
Отдельных селекторов, группы «Обычные» и группы WL нет.

Сохраняются исключения по именам: Russia, Belarus, Ukraine и отдельные метки WL и SS.
Удаление селектора WL не включает такие узлы в автоматический пул.
URL проверки — YouTube favicon, интервал — 180 секунд, tolerance — 100 мс.
Публичный шаблон и генератор используют одинаковые правила и настройки пула.
Группы профиля Shadowrocket не меняются.

## Генератор в браузере

[Откройте генератор](https://simonerrror.github.io/ShadowRocket/clash/).
Одна форма содержит подписки, файлы Mihomo YAML/JSON, WG/AWG `.conf`,
OpenVPN `.ovpn`, ZIP и отдельные URI узлов. Дополнительно можно задать
DNS-over-HTTPS, Smart DNS и IPv4 его релея.
Добавьте хотя бы один источник узлов; остальные поля необязательны.
Допускается до 100 файлов и до 16 МиБ данных во всём наборе после распаковки ZIP.

Выберите «Скачать для FlClash / Mihomo» или «Скачать для Clash Mi».
Генератор создаёт локальный YAML с вашими входами. Для Clash Verge Rev используйте
выход FlClash / Mihomo. В выход Clash Mi дополнительно включены начальные снимки
публичных списков правил; DNS и маршрутизация берутся из той же основы.

Введённые ссылки и файлы обрабатываются в памяти вкладки. Они не отправляются
на сервер, не записываются в хранилище браузера, URL страницы или аналитику.
Страница не проверяет доступность подписок. Их загрузит VPN-клиент после импорта.
Скачанный YAML содержит ваши данные доступа; храните его у себя.
Кнопка «Очистить» удаляет введённые значения и выбранные файлы.

### Как проверить обработку без отправки

- Исходный код и версия сборки доступны в открытом репозитории.
- В HTML встроены стили, скрипт и публичные исходные данные; CDN не используются.
- [CSP запрещает сетевые соединения](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/connect-src)
  и [отправку форм](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/form-action). Разрешён только встроенный
  скрипт с указанным SHA-256, без `unsafe-inline` и `unsafe-eval`.
- В инструментах браузера откройте Network, очистите журнал и соберите конфиг
  на тестовых данных: генерация не должна создавать сетевых запросов.
- Для автономного использования нажмите «Скачать офлайн-генератор» **до ввода
  своих данных**, отключите сеть и откройте скачанный HTML. После сборки закройте вкладку.

Эти меры относятся к проверенной версии страницы. Они не защищают от расширения
браузера, которое читает поля, или от последующей подмены HTML на хостинге.
Для независимого использования сохраните проверенную локальную копию.

## Подготовка подписок

[`clash_config.yaml`](../clash_config.yaml) — шаблон для Mihomo. Ссылку на вашу
подписку нужно вписать в локальную копию до импорта:

```yaml
proxy-providers:
  Main-Sub:
    type: http
    url: "<INSERT_SUBSCRIPTION_URL_HERE>"
```

Замените только значение `url` на полный HTTPS-адрес своей подписки,
совместимой с Mihomo. Остальные поля блока `Main-Sub` сохраните.

Для нескольких подписок:

1. Скопируйте полный блок `Main-Sub` внутри `proxy-providers` для каждой новой подписки.
2. Задайте каждому провайдеру отдельное имя, например `Second-Sub`.
3. Впишите соответствующий URL и уникальный путь к кэшу, например `./proxies/second.yaml`.
4. Добавьте имя провайдера в `use` группы **Режим**.

Ссылки на подписки храните в локальном профиле. Они могут содержать данные доступа.

## Импорт в Clash Verge Rev

1. Установите приложение из [официального выпуска](https://github.com/clash-verge-rev/clash-verge-rev/releases).
2. Скачайте [`clash_config.yaml`](https://raw.githubusercontent.com/Simonerrror/ShadowRocket/main/clash_config.yaml)
   и заполните подписки по инструкции выше.
3. Откройте **Профили → Новый** и выберите тип **Local**.
4. Задайте название профиля и выберите подготовленный файл.
5. Активируйте профиль и включите режим **TUN**. Если приложение запросит установку
   необходимого компонента TUN, выполните её через интерфейс клиента.
6. Откройте группу **Режим**, проверьте наличие узлов и запустите проверку задержек.
7. Проверьте доступ к нужным сайтам через выбранный узел.

Пустая группа может означать, что подписка не загрузилась либо имена узлов
не прошли фильтр. Сверьте URL провайдера, формат подписки и названия узлов.
Результат проверки задержки отдельного узла не подтверждает работу всех сайтов.

Локальный профиль не заменяется автоматически новой версией шаблона из GitHub.
Списки правил обновляются по URL из `rule-providers`. При обновлении самого шаблона
сохраните свои провайдеры и повторно укажите подписки в новой локальной копии.
